# 2026-10-26 本地发布与真实受控回归

## 根因与修复范围

- 真实 root_preview 只保存包目录，本来不会增加作品；directory_preview 也曾禁止所有真实识别，导致实际媒体无法进入审核队列。现在仅对该任务成功返回的媒体节点排本地识别任务，不递归、不读 NFO、不调用 TMDB。包目录不作为作品。
- 文件名推断暂时只在同来源、同目录内按明确名称/年份或季集归组；没有强外部标识不跨来源合并。新条目进入 review，管理员通过正常审核 API 后才能公开。既有审核状态、NFO 海报证据和人工锁定保留。
- 原扫描异常只更新任务和访问状态，没有记录 HealthEvent。现在根目录异常记录分享健康，指定目录异常只记录目录健康，旧 worker 不能覆盖新租约。健康规则仍是首次 missing 为 pending，第三次明确 missing 才隐藏；不确定错误不累计。
- 演示分享原来带可点击的假外链。现在 mock 版本的 share_url 为空，并显示演示说明。真实链接由固定分享码和当前访问码构造，原始 source.url 不覆盖，不生成子目录直达链接。
- 海报没有可用公开 URL 不是图床故障；不再用无说明的封面假装海报。白名单规则保留，浏览器失败时显示原因。分享、节点和网页验证状态独立展示，不把 API 可读当成网页已打开。

涉及 app 的 worker、scan_scope、identify_impl/identify_fixed2、health、catalog、security、posters；前端 Poster、Detail、Catalog、api；新增受控验证脚本、回归测试与 compose.preview.yaml。没有重写技术栈，没有新增业务表或数据库迁移版本，没有新增媒体读写 API。

```powershell
docker stop medianest-preview-20261026-web-1
docker start medianest-verify-20261025-2b708b07-web-1
```

两条命令分别停止新预览、恢复旧镜像，数据卷不删除，不执行 down -v。数据库结构不变，通常不需要恢复备份。若确需恢复发布前数据，必须先停所有挂载该卷的进程，将当前库及 WAL/SHM 连同密钥另存为恢复前快照，再离线恢复这一明确备份的 verify.db 与配套密钥；不要直接覆盖运行中的 SQLite。该破坏性数据恢复需要用户明确确认，本轮不执行。
