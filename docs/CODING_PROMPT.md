# 映集（YINGJI INDEX）代码实现提示词

你是负责维护本仓库的资深全栈工程师。请在现有代码基础上迭代，不要重写项目，不要引入与现有技术栈冲突的框架。产品是“115 分享大包影视索引站”：只建立可检索的目录索引和元数据，不转存、不移动、不重命名、不下载、不播放任何影视内容。

## 不可突破的边界

1. 不得访问用户此前提供的真实 115 分享链接；测试只能使用仓库内的虚构 `demo*` URL、脱敏链接和模拟目录。
2. 不得调用 115 转存、移动、重命名、下载、播放或领取接口。`p115client` 只能用于分享分页和受限的只读元数据读取。
3. 默认关闭真实 115 和 TMDB；只有显式配置和授权后才允许小范围验证。任何测试不得依赖公网、真实账号或真实海报。
4. 服务器不缓存源包海报、背景图、原始 NFO 或视频。公开海报由浏览器直接加载，并且必须经过 HTTPS 域名白名单校验；不能把访客提交的 URL 变成任意服务端抓取请求。
5. 前台可以展示原始分享链接、访问码和完整目录路径，但不能伪造不可验证的子目录直达链接。

## 业务目标

- 批量粘贴多条 115 分享链接，解析 URL 内 `password` 或独立访问码，进入持久化任务队列。
- 每个管理员维护自己的分享源和任务视图；公共作品库可合并展示，但来源、凭据、任务和审计记录必须隔离。
- 支持电影、电视剧、综艺、动漫、演唱会和 ISO/BDMV 原盘。ISO/BDMV 是作品的“原盘版本”，BDMV/STREAM 内部文件不能误生成独立作品。
- 浏览入口同时支持作品、演员、合集；详情页展示版本列表、清晰度、音轨、字幕、原盘标记、源分享、完整目录路径和健康状态。
- 同一作品的多个版本默认合并到一个作品条目下，按版本列表展示；只有强 TMDB/IMDb/NFO ID 或高置信度规则才能跨来源自动合并，低置信度进入待确认队列。
- 电视剧按剧集→季→集组织；同一剧集的多分辨率、不同音轨、字幕和原盘版本作为版本/文件节点，不重复创建作品。
- `.nfo` 优先于目录名和文件名；没有 NFO 时用 GuessIt 和目录规则推断。TMDB 仅在显式启用后补全名称、年份、类型、演员、外部 ID 和海报。
- 普通访客可提交片名、年份、海报、目录纠错建议；建议限流、记录来源和 IP 摘要，任何修改必须由管理员审核并写入审计日志。后台待确认项目不在前台展示。
- 健康检查拆成分享、目录、文件三级。第一次明确不存在标记 `pending`；连续达到 `FAILURE_THRESHOLD`（默认 3）次明确不存在后才标记 `missing` 并隐藏。超时、限流、认证失败、分页不完整和未知错误不得当作失效。

## 技术约束

- 后端继续使用 FastAPI、SQLAlchemy、SQLite 默认，PostgreSQL 通过 `DATABASE_URL` 可选。
- 前端继续使用 Vue 3、TypeScript、Vite、Nuxt UI；保持深色影院风格和移动端响应式布局。
- 任务必须持久化，支持分页 checkpoint、lease token fencing、暂停、重试、续跑和管理员查看失败原因。
- NFO XML 解析使用 defusedxml；密码等私密字段使用现有加密机制；密码永不回显到日志。
- 所有输入有长度、数量和频率限制；登录使用安全密码哈希；保留 CSP、CSRF/会话安全、SSRF 防护、审计日志和来源隔离。

## 推荐的数据模型

至少维护 `Admin/User`、`Source`、`Share`、`Task/Job`、`Work`、`Variant`、`MediaNode`、`Person`、`Collection`、`Suggestion`、`HealthCheck`、`AuditEvent`。来源节点应保存分享码、访问码加密值、外部分享 URL、完整路径、父目录和节点 ID；作品保存规范化名称、年份、类型、NFO/TMDB/IMDb ID、海报 URL 和置信度；版本保存 4K/1080P、音轨、字幕、原盘/文件夹、大小和健康状态。

## 识别与合并规则

1. 节点类型优先级：NFO 显示类型 > 目录结构 > 文件名扩展名/GuessIt。
2. 电影文件、ISO、BDMV 根目录创建媒体版本；BDMV/STREAM 下的 `.m2ts` 只作为节点详情。
3. 影视剧从 `S01E02`、`Season 01` 等模式识别季集；同剧多版本归并到同一作品。
4. 清晰度、来源、语言和字幕必须结构化保存，不要把所有信息塞进标题。
5. 无法确定的名称或合并关系只能进入后台待确认，不能静默覆盖已有作品。

## 页面与 API 验收

- 前台：搜索、类型筛选、年份/清晰度/字幕/原盘筛选、作品详情、演员页、合集页、版本展开、失效隐藏状态。
- 后台：批量导入、任务队列、管理员自己的来源、识别待确认、健康待复检、建议审核、审计日志、TMDB/公开图片域名配置。
- API 必须覆盖登录后立即读取当前用户、来源隔离、批量导入、目录分页、识别、健康检查、建议提交和审核。
- 不提供领取、转存、下载、播放 API；如果未来新增，必须单独设计权限、风控和用户确认，不得在本轮偷偷加入。
